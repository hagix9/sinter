:::caution[未リリース]
`nm_connection` は v1.15.0 向けに実装済みですが、まだリリースされていません。
最初の実機測定(Rocky Linux 9.8 と 10.2)で見つかった 2 件の不具合は修正済みです。
NetworkManager がチェックポイントの作成を拒否する点と、IPv6 の値を含むプロファイルを
読み取れない点です。修正後のコードでの活性化・非活性化・チェックポイントとその
ロールバックは、実機でまだ測定していません。測定が済むまでは、Sinter が正確に
読み取れないものはすべて拒否し、推測では通しません。
:::

**目的:** NetworkManager の接続プロファイル(`connection.id`)を 1 つ宣言する。
種類は Ethernet で、インタフェース、autoconnect、IPv4/IPv6 の設定、存在するか、
必要ならアクティブかを管理する。

## 書式

```yaml
- id: lan
  type: nm_connection
  with:
    name: lan
    ifname: eth1
    autoconnect: true
    ipv4:
      method: manual
      addresses: [198.51.100.10/24]
      dns: [198.51.100.53]
      dns_search: [lab.example.net]
    ipv6:
      method: ignore
    active: true
```

## パラメータ

| パラメータ | 必須 | 型 | デフォルト | 説明 |
|-----------|------|----|-----------|------|
| `name` | はい | 静的な文字列 | — | `connection.id`。印字可能な ASCII で 1〜64 バイト(`\` は不可)。先頭は `-` 不可、前後の空白不可。この名前のプロファイルはちょうど 1 つでなければならない。 |
| `type` | いいえ | 文字列 | `ethernet` | v1.15.0 では `ethernet` のみ。 |
| `ifname` | いいえ | 文字列 | — | `connection.interface-name`(1〜15 バイト、`[A-Za-z0-9_.-]`)。 |
| `autoconnect` | いいえ | 真偽値 | — | `connection.autoconnect`。 |
| `ipv4.method` | いいえ | 文字列 | — | `auto`、`manual`、`disabled`。 |
| `ipv4.addresses` | いいえ | リスト | — | プレフィックスつき IPv4 アドレス(`192.0.2.10/24`)。順序を保つ。 |
| `ipv4.gateway` | いいえ | 文字列 | — | IPv4 アドレス。なしは `""`。 |
| `ipv4.dns` | いいえ | リスト | — | IPv4 アドレス。順序に意味がある。 |
| `ipv4.dns_search` | いいえ | リスト | — | DNS 名(RFC 1123 のラベル、小文字、253 バイト以下)。 |
| `ipv6.method` | いいえ | 文字列 | — | `auto`、`manual`、`ignore`、`disabled`、`link-local`。 |
| `ipv6.addresses`、`ipv6.gateway`、`ipv6.dns` | いいえ | — | — | IPv4 と同じ。IPv6 は正規形(RFC 5952)。 |
| `state` | いいえ | 文字列 | `present` | `present` または `absent`。 |
| `active` | いいえ | 真偽値 | — | プロファイルをアクティブにするか。 |
| `checkpoint_timeout` | いいえ | 整数 | `90` | チェックポイントのロールバックタイムアウト(秒)。30〜600。 |

- 比較・変更するのは宣言したフィールドだけ。プロファイルのほかの設定はそのまま残る。
- `method: manual` には少なくとも 1 つのアドレスが必要。アドレスとゲートウェイを
  使えるのは `manual` のときだけ(ほかの組み合わせはまだ測定していない)。
- `state: absent` で使えるのは `name` だけ。
- 802.1X、Wi-Fi、VLAN、bond、bridge、秘密情報を含む設定は対象外。未知のフィールドは検証エラー。
- 同じ `name` の `nm_connection` が 2 つあると検証エラー。
- ほかの種類の既存プロファイルを変更・削除することはない。

## 期待される動作

- 事前検査: `NetworkManager.service` がアクティブで、`/usr/bin/nmcli` があること。
  満たされなければ、足りない部品を示してリソースは失敗する。Sinter が NetworkManager
  をインストールしたり起動したりすることはない。
- 観測には、フィールド一覧を固定した `nmcli` の terse 出力を使い、厳密に
  解析する。フィールドの欠落・重複・未知、未知の値、遷移中のプロファイルは
  エラーで、drift にはしない。設定の各行は、最初のコロンまでをフィールド名、
  その後ろを値として読む(NetworkManager は IPv6 の値のコロンを escape せずに
  出力する)。値にバックスラッシュや制御文字があれば拒否する。同名のプロファイルが 2 つあればエラー。
- 変更は固定 argv(`nmcli connection add|modify|up|down|delete`)で行い、shell は
  使わない。観測した UUID を使うので、途中で名前を変えられたり差し替えられたりした
  プロファイルを変更することはない。変更後にもう一度観測し、宣言したすべての
  フィールドを検証する。
- `active: true` は、プロファイルが変わったか非アクティブなときに有効化する。
  `active: false` は無効化する。`active` がない場合、アクティブなプロファイルを
  変更しても**再有効化しない**。デバイスは、NetworkManager が次にプロファイルを
  有効化するまで(たとえば起動時)今の設定のまま動く。plan と apply はその旨を表示する。
- 同じレシピの 2 回目の apply は何も変えない。
- audit は読み取り専用で、宣言したフィールドごと、存在、(宣言時は)アクティブ状態の
  drift を返す。
- MCP では使えない。

## 管理接続とチェックポイント

すべての変更は接続リスク区分 C([接続リスク制御](/ja/reference/cli/)を参照)。
Sinter が使う SSH 接続の管理インタフェースとクライアントアドレスについて、
次のいずれかに当たる変更は管理接続に **affects**(影響する)とする。プロファイルの
インタフェース(変更前または後)が管理インタフェースである、プロファイルが管理
インタフェースでアクティブ、インタフェースなしで autoconnect する、またはインタフェースなしで有効化される(NetworkManager がデバイスを選ぶ)、管理インタフェース
でアクティブなまま無効化または削除される、クライアントアドレスへの経路を変えうる
(自動アドレス設定(DHCP やルーター広告)、ゲートウェイ、クライアントアドレスを含む
プレフィックスのアドレス。作成するプロファイルや、autoconnect する非アクティブなプロファイルを変更する場合は、NetworkManager が自分で有効化しうるので、そのアドレス設定も数える)。どれにも当たらない変更だけが **clear**(たとえば管理用
でないプロファイルの DNS 設定)。bridge・bond・team の port プロファイルは **unknown**。管理インタフェースが素の Ethernet デバイスでない(bridge、bond、team、VLAN)場合も、すべての変更が **unknown** になる。経路を読み取れなければ **unknown** で、変更は拒否
する。ローカルのターゲットには見える管理接続がないため、そこではすべての変更を拒否する。

`affects` の変更には承認が必要で、NetworkManager のチェックポイントの中でだけ実行する。

1. `busctl` でチェックポイント API(`CheckpointCreate`、`CheckpointDestroy`、
   `CheckpointRollback`)と権限を確認する。使えない、または拒否された(たとえば
   polkit)場合は、何も変更する前にリソースは失敗する。
2. 管理デバイスとプロファイルのデバイスを対象に(すべてのデバイスを対象にする
   ことはない)、ロールバックタイムアウト `checkpoint_timeout` のチェックポイントを
   作る。チェックポイントがある間に作られたプロファイルは、ロールバックで削除される
   (NetworkManager はこれをホスト全体に対して行うので、ほかのツールがその間に作った
   プロファイルも削除されることがある)。
3. 変更を適用し、新しい SSH 接続(ホスト鍵を完全に検証し、`/usr/bin/true` を実行)を開く。
4. 成功したらチェックポイントを破棄し(変更は残る)、検証する。失敗したら、元の
   接続が応答すれば明示的にロールバックし、応答しなければタイムアウト + 15 秒
   待って再接続する。ロールバックを検証できればリソースは失敗(exit 5)、
   それ以外は不確定(exit 6)。

チェックポイントを使えるのは、変更がすぐに効く(プロファイルを有効化する、または
アクティブなプロファイルを無効化・削除する)うえに、対象デバイスがわかる場合だけ。
次の有効化や起動のときにはじめて効く変更や、インタフェースなしで autoconnect する
プロファイルは、今はテストできないので承認があっても拒否する。

チェックポイントの作成・破棄・ロールバックは承認 ledger に記録する。チェックポイント
作成後に Sinter が中断した場合、NetworkManager はタイムアウトの時点で、うまくいった
変更でもロールバックする。ledger にはその実行が中断として残る。

**制限:** チェックポイントで戻せるのは、NetworkManager が動き続けている間の
NetworkManager の設定だけ。NetworkManager の再起動、OS の再起動、NetworkManager の
外の経路やフィルタ、Sinter 以外のセッションは対象外。回復は保証しない。
