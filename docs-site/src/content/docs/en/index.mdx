**Small enough to understand, strong enough to trust.** Sinter describes and
applies operating-system configuration from a single Rust binary — no agent,
no Ruby or Python runtime, on the managed host.

```yaml
version: 1

resources:
  - id: tree
    type: package
    with:
      name: tree
      state: present
```

```sh
sinter validate recipe.yaml
sinter plan --host server.example.com recipe.yaml
sinter apply --host server.example.com --sudo recipe.yaml
sinter audit --host server.example.com --sudo recipe.yaml
```

## Key characteristics

<CardGrid>
  <Card title="Agentless, single binary" icon="rocket">
    Managed hosts need only OpenSSH, `/bin/sh`, systemd, and `sudo -n` — no
    Sinter runtime is installed on the target.
  </Card>
  <Card title="Read-only plan and audit" icon="magnifier">
    `sinter plan` previews what an apply would change; `sinter audit`
    reports whether the target already matches the recipe — neither mutates
    or executes command resources.
  </Card>
  <Card title="Idempotent by design" icon="approve-check">
    Applying the same recipe twice performs zero mutations when the target
    already matches the desired state.
  </Card>
  <Card title="Fail closed" icon="warning">
    Unknown SSH host keys, unsafe paths, unexpected symlinks, and verification
    failures stop execution instead of guessing.
  </Card>
</CardGrid>

## Supported platforms

| Platform | Architecture | Package backend |
|----------|--------------|-----------------|
| Ubuntu 24.04 LTS | amd64 | apt |
| Ubuntu 26.04 LTS | amd64 | apt |
| Rocky Linux 9 | x86_64 | dnf |
| Rocky Linux 10 | x86_64 | dnf |

Acceptance references: Rocky Linux 9.8 x86_64 (DNF 4.14.0), Rocky Linux 10.2
x86_64 (DNF 4.20.0), Ubuntu 24.04.4 amd64, Ubuntu 26.04.1 LTS amd64.
See [Compatibility](/sinter/en/compatibility/platforms/) for the full matrix and
requirements.
