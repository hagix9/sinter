# v1.16.0 release and acceptance plan (real-host acceptance of the eight targets)

Status: PLAN, 2026-11-27. Nothing in this document has been run. Creating, starting or changing any GCE resource, any paid operation, any change or reboot of a real host, push, tag and Release all wait for the Owner's approval of this plan. The candidate is the local branch `work/v1.16.0` (base: v1.15.0, `31e340b1`). The previous release's runbook (RELEASE.md, R8 runner, `release/acceptance-harness/`, the cost tool `overall_cost.py`, the evidence layout and the approval set) is reused unchanged unless this plan says otherwise.

## 1. What changed since v1.15.0 that real hosts must show

Everything below is tested only against Sinter's scripted target, except a read-only measurement on one Rocky Linux 10.2 (aarch64) host (`audit-artifacts/v1.16.0-dev-2026-11-26/MEASUREMENT.md`, `os-probe.masked.txt`, `tuned-probe.txt`).

- Core: bundle planning per host and nested bundles (DESIGN §19.3, §49.1), `creates_accounts` (§49.2), `directory` `parents: true` (§49.3), audit of a host nothing is applied to (§49.4), undefined template variables at load (§49.5), declared backups in a partial run (§49.6).
- Parents others can write to: `allow_writable_parents` and the read-only audit below such a parent (§63), including the removal of Sinter's own staging directory there (§63, staging cleanup).
- New built-in types: `file_merge` (§50), `dnf_repository` (§51), `dnf_module` (§52), `crypto_policy` (§53), `sysctl` (§54), `hostname` (§55), `tuned` (§57), `timezone` (§60), `locale` (§61), `kernel_module` (§62).
- Not in scope for changes: `kernel_args` and `grub` (design only, §58). No check changes boot configuration, and no host is rebooted.

## 3. Safety choices for the checks

- Nothing that can cut the management connection is changed: no firewall or network change beyond what v1.15.0 already checks, no `sshd` restart, no reboot.
- `crypto_policy` changes the policy only on EL 9, to a stricter one and back; `sshd` keeps the policy it started with until it is restarted, and the harness restarts nothing. On EL 10 only refusals and a no-change run, because the stricter modules of EL 9 do not exist there and switching the base policy (`FUTURE`) can affect the package repositories' TLS.
- `hostname`, `timezone`, `locale`, `sysctl` and `tuned` record the original value first and restore it at the end of the check, also after a failure (the harness's existing restore traps). `kernel_module` uses `dummy`, which no service needs; Sinter never unloads, so the check leaves it loaded until the VM is deleted (acceptable on a disposable target).
- `allow_writable_parents` runs in a directory the harness creates for the check (`/opt/sinter-acc-writable`, mode 0777) and deletes afterwards.
- Every check runs on a disposable target that is deleted after the evidence is copied and verified (Owner rule of 2026-11-18).

## 4. Assumptions the run must measure (NOT VERIFIED today)

Collected from the independent audits A to E and the DESIGN sections; each becomes a check line or an observation recorded in the evidence:

- `stat -c '%F|...|%z|%h'` output, ctime changes on rename/link/unlink, link counts, and the identity checks of §63 on ext4/xfs of the GCE images; `dd iflag=nofollow,nonblock` behaviour; the staging script in a non-sticky 0777 directory as root (publish new, publish replace, cleanup by owner, group and inode).
- `systemd-analyze cat-config sysctl.d` on EL 9 and Ubuntu (header lines, masked files, order across directories; audit E: E-NV1 to E-NV3) and whether `/etc/sysctl.conf` is included.
- DNF: `/usr/bin/dnf` link target on every RHEL-family image; repository files written by Sinter read back by `dnf repolist`; a package installed from a new repository (PGDG) including the first key import with `-y`; `/etc/dnf/modules.d/<name>.module` after enable, disable and reset.
- `update-crypto-policies --show`/`--set` exit codes and output; policy and module files per release.
- `tuned-adm` (`profile`, `off`, `recommend`, `verify`), `/etc/tuned/active_profile` after each, the unit name; that `recommend` and `verify` change nothing.
- `hostnamectl --static`/`--transient`/`set-hostname` (and whether a pretty name is cleared); `timedatectl set-timezone` link form; `localectl set-locale` effect on unmanaged keys; `locale -a`; `modprobe -n -v` changes nothing; `/sys/module/<name>` after a load.

## 5. Order and stop conditions

1. Harness work, local only, no cost: add the checks of §2 and §4 to `release/acceptance-harness/acceptance-target.sh`, `expected-check-ids.txt` and `applicability.json`, extend the stand-in tests, and pass an independent review of the harness change. Then the RC commit (version 1.16.0 in `Cargo.toml`, CHANGELOG section, `RELEASE.md` unchanged), as before.
2. p3, Linux gate on a new gate host (Ubuntu 24.04, `e2-standard-4`): the full root test suite and the strict gate, as in v1.15.0.
3. p4, build on a new builder: the frozen artifact.
4. p5, the eight targets one after the other with the frozen artifact.
5. Evidence copied, checksums verified, Steps 10 to 13 staged and verified (the approval-set verifier now reads the `not_applicable` end line without an exception), independent review, then the Owner's publication approval (Steps 14 to 17).

Stop conditions (all paid operations stop, VMs are stopped, the evidence collected so far is kept): the cost tool reports `cumulative + planned` above the safe-stop amount; a target loses its management connection and does not come back within the existing timeout; a check fails in a way the plan did not foresee (no automatic re-run: a new round needs its own approval as before); any GCE resource outside this plan is found started or changed by the run.

Recovery: the v1.15.0 procedures apply (serial console access for a stuck boot, the dnf-automatic quiesce driver, the cleanup-ssh retry). A target that cannot be brought back is deleted after its evidence is copied.

Cleanup and residual billing: after the evidence is verified, the gate host, the builder and the eight targets are deleted with the existing delete plan; a read-only listing confirms that no instance or disk of the run is left. Out of scope and left as they are: a pre-existing static IP address, router and Cloud NAT, whose standing costs continue independently of this run.

## 6. Cost estimate (list prices, the rates of `overall_cost.py`)

Rates: targets 0.03 USD/h (RHEL 0.09 USD/h), gate host 0.19 USD/h, builder 0.09 USD/h, disks 0.95 USD per 240 GB per day (240 GB in total while all exist), plus 0.10 USD of target time not seen in the ledger per acceptance round.

Duration basis: v1.15.0 took 12 to 23 minutes per target for 76 checks; the new checks add an estimated 15 to 25 minutes (PostgreSQL from PGDG on six RHEL-family targets, TuneD installation, the type checks), so about 40 minutes per target and about 1 hour of VM time per target including start, preparation and stop. v1.15.0's cost was dominated by disks (about 2.4 USD of 5.08 USD) because the targets existed for 2.5 days across several rounds.

| Gate host | 1.5 h: 0.29 USD | 3.0 h: 0.57 USD |
| Builder | 1.0 h: 0.09 USD | 2.0 h: 0.18 USD |
| Disks (240 GB) | 1.5 days: 1.43 USD | 3.0 days: 2.85 USD |
| Unseen acceptance time | 0.10 USD | 0.30 USD |
| **Total** | **about 2.3 USD** | **about 4.6 USD** |

Proposed limits for the Owner: an absolute cap of **5.00 USD** and a safe-stop amount of **4.50 USD** (no phase starts when `cumulative + planned` for it exceeds 4.50 USD). The largest saving is time: create the targets only when p5 is ready to start, and delete everything as soon as the evidence is verified.

## 8. Advice for users about the `systemd_timer` fix

Up to v1.15.0, when a `systemd_timer` field such as `on_calendar` or `description` came from a variable marked `sensitive: true`, and the unit file on the host differed from the declared one, `sinter plan` (text output only) showed the value in its diff. JSON output, apply and audit were not affected. Users who keep plan output (CI logs, saved terminal output) of such recipes should check that output and, if a real secret was used there, treat it as exposed and replace it. Sinter cannot find such logs for them, and this release does not search for them.
