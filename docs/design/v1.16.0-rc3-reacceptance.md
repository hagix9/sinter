The record is `V1160-P5-R1-STOP-REPORT-2026-11-27.md` (sha256 `5748ba20db0eb218270fc94826730840dac927aad14c13640b37a48bd8aba663`). | Failed check | Cause (established) | Fix in RC 3 |

## 3. The existing eight targets cannot be reused (checked in the pinned tools)

- gate2 and the builder of run `v1160r1` are deleted (DELETED_VERIFIED). RC 3 needs a gate host for p3 and a builder for p4.
- The pinned VM tool (`relv-vmctl.sh`, exec copy v1141, sha256 `3b7a3f0b…`) refuses to create a VM whose name has any create attempt on record: "names are never reused", also across runs ("appears in the ledger of another run"). So gate2 and the builder cannot be created again in run `v1160r1`, and the tool never adopts a VM it did not create.
- The VM names carry the run id (`sinter-v180-…-v1160r1`), so a new run cannot address the existing targets either.

Therefore RC 3 runs as a new run (proposed `v1160r2`) with ten new VMs, and the eight TERMINATED targets of `v1160r1` only cost money (0.633 USD/day of disk). Recommendation: delete them now, with the existing delete plan of stage `targets` and the verified p5 evidence manifest (`p5.EVIDENCE.sha256`, sha256 `b77739f7…`, 63/63 OK), as plan §9 item 2 allows after the evidence is verified. This needs the Owner's word because the Owner asked to keep them for reuse.

What the new run checks instead of the reuse checks: each VM is created by the run itself (instance and boot disk ids pinned in the ledger), its image is the pinned image, its SSH host keys are pinned at creation (`hostkeys`, `pin s2` after a serial-console loss), it starts from a fresh image (no residue of an earlier test), and every stage re-verifies the id before it acts.
